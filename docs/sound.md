# Sound: the Sound Images drivers, the driver API, the music data, and the JS port

Evidence tags as in `CLAUDE.md`. Addresses: `1000:xxxx` = Ghidra program `MICROU.EXE` (`DS = 193C`); `DRIVER1.BIN+0xXXXX` / `DRIVER2.BIN+0xXXXX` = file offsets, which equal segment offsets because the module is loaded at offset 0 of segment `2424` (live `1662`). Established by the `mm-sound-research` fan-out (four mapping agents incl. a live DOSBox trace), then ported to `src/formats/si2.js` + `src/audio/` and verified as described in §7.

## 1. Architecture `[PROVEN]`

- **All music, sound effects and instruments are embedded in the driver binaries.** `MICROU.EXE` passes no data pointers — only tune numbers, sfx ids and, for engine sounds, bytes it pokes into the driver's own memory. There is **no PCM / Sound Blaster DSP path**: the probe at `1000:3a8d` is dead code (no callers), `DS:262D` stays 0, the DSP reset `OUT` never fires, and neither binary contains a `22xh` port immediate. "BLASTER" in the options means **OPL2/AdLib**.
- `SETTINGS.DAT` word 3 = `DS:[0F64]` selects the module: 0 → `DRIVER0.BIN` (null, 8 B), 1 → `DRIVER1.BIN` (OPL2), 2 → `DRIVER2.BIN` (PC speaker). `LoadSoundDriverBinModule 1000:321c` reads the whole file into `2424:0000`, then `AH=0, DX=388h` (init) and `AH=2, CX=4287h` (set tick rate; loops until AL = 0). Live: `DRIVER0.BIN` is resident at GAME OPTIONS (the slot still holds `FONT.BIN` residue behind it); `DRIVER1.BIN` is loaded — twice back to back (`1000:0051`, `1000:0066`) — when RETURN is pressed.
- **One far entry, AH = command** (`DispatchCommand DRIVER1.BIN+0x94`: jump table at `+0xC4`, 12 handlers; `+0xC3` holds the max command, set to 0x10 by init). AX is the only return register. The `+4` IRET entry exists but is never installed or called.
- **The tick**: the game's IRQ0 ISR `1000:489c` waits for vertical retrace, re-locks the PIT (`DS:2614` = 16875), increments the game tick `DS:28F7`, then — **only while `CS:3279 == 1`** (cleared/set around the driver load) — calls `AH=3`. Measured live: 700 ticks per 10 s = **70.0 Hz**. `AH=2`'s `CX=4287h` (17031) is the nominal PIT reload the driver uses for its own arithmetic: interrupts/min = `0x04446390 / 0x4287` = 4203. **The gate is visible in the captures**: a tick whose counter increment lands inside the 28 KB driver load skips the driver, and whether one does is session-dependent — it did in `live_title_start` (counter 53051→53052 during the load) and did not in `live_title_cold` (the game's first post-load `AH=9` is logged on the load's own tick). Both are covered by one rule, **the first driver tick is the one after the game's first post-load command** (`AH=9` at `1000:0073`, issued straight after the load returns); moving the first driver tick by one in either direction breaks both captures (`[PROVEN]`, `tools/check-si2-live.mjs`): one idle tick more or fewer before the tune starts shifts the accumulator phase and diverges after exactly 183 writes (more idle ticks diverge elsewhere — the index follows the 16.16 fraction, not the tick count), and delaying the tune's start tick itself matches nothing. The gate's audible effect is confined to the tune's first ~14 ms.

Commands 4/6/7 only set a pending byte (`+0x125A/+0x125D/+0x125C`); 5/8 push into 8-entry queues (`+0x13D1`/`+0x13D9`). **The work happens in the next tick**, in this order (`CmdTick`): `DoPendingReset` → `DoPendingStopMusic` → `StartPendingTune` → sfx stop queue → sfx start queue → accumulate → advance the 16 slots → clear the integer parts.

Two quirks that the live capture exposed and the port reproduces:
- `DoPendingStopMusic` loops over `[+0x1258]` = the track count of the **last started** tune and `JCXZ`-skips the whole routine — **including clearing the pending flag** — while that count is 0. The title screen issues `AH=7` *before* its first `AH=4` on a fresh driver, so the stop fires one tick **after** the tune starts (keying its notes off), and the game's `AH=9`/`AH=4` pair then restarts it (everything but the key-on bits deduplicated by the shadow compare). `[PROVEN]`.
- `StartPendingTune` resets only `state, loop, counter, pos, bend range, bend, perc, inst#, volume` of a slot; `b0` (key-on shadow), channel, op offsets and instrument pointer survive.
- The same `DoPendingStopMusic` loop frees slots `0..trackCount-1` **regardless of their state** — so the `AH=7` the game issues at the end of the round-file load (`1000:39F5`, ~20 ticks into the race) keys off and frees the four **engine sfx** that had just started in slots 0–3 (`trackCount` = 5 from tune 4); the game's `AH=10`/`AH=5` keep-alive restarts them a few ticks later. `[PROVEN]` (race replay).
- Engine records are written **silently** when a car's pitch byte is 0: the per-frame update (`1000:7B46`) stores `0` and `0x91` (END) into the record and issues no command for that car; the engine then ends at its next loop iteration (`A0` re-written with bend 0, then key-off). A car reappears in the batch with `AH=10` → `AH=5` when its speed is non-zero again. `[PROVEN]` (race replay: the cars missing from a batch are exactly the ones whose engines end).

## 3. `DRIVER1.BIN` internals `[PROVEN]` (disassembly + live register shadow)

Layout: code `0x0000–0x09D2`; tables `0x09D3–0x114C`; variables `0x114D–0x13F5`; **music bank `0x13F6`** (8 tunes, 47 tracks, packed to `0x652E`), **sfx bank `0x65B4`** (18), **instrument bank `0x6751`** (0x80-byte percussion map — all zero — then 128 × 16-byte instruments to EOF). Pointer words `0x13F0/0x13F2/0x13F4`.

- **OPL write layer** `OplWriteIfChanged +0x175`: compares with the 256-byte shadow at `+0x114D`, writes index to `[+0x1252]` (388h) and data to +1 with PIT-channel-2 busy waits. `OplWriteAlways +0x19D` is used only by the reset list. Live: all 5600 music/sfx writes went through the compare route — **the register stream is de-duplicated**.
- **Init with DX≠0 skips OPL detection and never writes reg 01, 08 or BD**; nothing else in the launch chain touches 388h/389h either (`SM.EXE`'s only port I/O is `IN 3DAh`, `IN 60h`, `OUT 20h`). Consequence: no rhythm mode, **9 melodic channels; music uses 0–7, sfx take the highest free channel from 8 down** (engines: car0→8, car1→7, car2→6, car3→5). **Waveforms are chip-dependent**: a real YM3812 gates the E0 waveform bytes behind reg 01 bit 5, which this game never sets — all sines. The DOSBox build behind every live capture (dosbox-staging fork, **Nuked OPL3** core) ignores reg 01 and honours waveforms 0–3 regardless, as an OPL3 card does in OPL2 mode — so the game *as heard under DOSBox* uses the instruments' waveforms (19 of 128 carry non-zero E0 bytes). The port defaults to the DOSBox/OPL3 behaviour (`new Opl2()`), with `strictOpl2: true` for the YM3812 reading. `[STATIC]` for the register facts; which one "sounds right" is a matter of target hardware.
- **Reset list** `+0x104A` (`AH=6`; the reset also zeroes 16 bytes at `+0x13D1` = both sfx queues): `40–45,48–4C,5D,50–55 := 3F`, `80–95 := FF`, `60–75 := FF`, `B0–B9 := 00` (the `5D` is a typo for `4D`; harmless).
- **Timing**: `RecomputeTickIncrements +0x98F`: `ipm = 0x04446390 / divisor` (4203); music increment (16.16) = `division·tempo / ipm` — **2 + 48555/65536 = 2.7409 sequence ticks per host tick** at 96/120; sfx increment = `0x1680 / ipm` = 1.3702 (sfx run at a fixed 96/s). `CmdTick` adds the increments to 32-bit accumulators (`+0x1265`, `+0x126D`), hands the **integer part to every slot at once**, then zeroes it — so events are quantised to 70.06 Hz with no drift. The accumulators' fractions start as the **file's** values, and the increments before the first tune are computed from the file's division/tempo at `+0x125E` (`C0 78` = 192/120 → 5.48/tick); the port seeds both from the image.
- **Voice slots**: 16 × 22 bytes at `+0x1271`: `+0` seq ptr, `+2/+4` 32-bit remaining-time counter, `+6` loop ptr, `+8` OPL channel, `+9` note, `+A` state (0 free / 1 music / 2 sfx), `+B` B0 shadow (bit 5 key-on), `+C/+D` op register offsets, `+E` instrument ptr, `+10` instrument #, `+11` volume (7F), `+12` sfx id, `+13` percussion flag, `+14` bend range, `+15` bend (40 = centre). `TickAdvanceSlot +0x273`: `SUB counter, n; SBB; JNC` — events fire on borrow, each event adds its following VLQ delay, loop while negative.
- **Sequence byte-code** (`+0x273` + event table `+0x327`): `stream := VLQ-delay event (VLQ-delay event)*`; VLQ = MIDI-style big-endian 7-bit groups (`ReadVarLenDelay +0x925`).

  | Op | Meaning |
  |---|---|
  | `00–7F nn vv` | NOTE ON note `nn` velocity `vv`: key-off the previous note (unless engine sfx ≥ 0x40 → legato), write A0/B0 (key-on), then the two 40h levels **after** the key-on |
  | `80–8F` | SET OPL CHANNEL `op & 0xF` (op offsets from `+0x1038`) |
  | `90 nn` | NOTE OFF IF `nn` == current note |
  | `91` | END TRACK (free slot; current tune := 0 when no music slot is left) |
  | `92 ii` | INSTRUMENT (loads 9 operator registers; resets volume 7F, bend 40; bend range := inst[F]) |
  | `93 t` | TEMPO (recompute increments) — never used |
  | `95 bb` | PITCH BEND (re-write A0/B0 if keyed) |
  | `96 vv` | VOLUME — never used; `97 f` PERC MODE — never used |
  | `98` | JUMP LOOP (to the `9C` point) |
  | `99` | NOTE OFF |
  | `9A` | SLEEP FOREVER (jumps to the `FF FF FF 7F 9A` stream at `+0x124D`) |
  | `9C` | SET LOOP point |
  | `9B x`, `9D x y`, `94` | skipped params / NOP; `FF` REST |

  Used in the shipped data: `8n` (47), `9C` (47), `92` (270), NOTE ON (3874), `99` (3771), `90` (103), `98` (47); sfx add `91` and `95` (13). All 8 tunes: division 96, tempo 120; tracks 7,8,7,5,5,6,4,5. **Tunes 1–3 loop** (their tracks open `00 8n 00 9C`; loop lengths 14208 / 12966–12967 / 12480 sequence ticks — tune 2's two track groups differ by one tick and drift apart by 5 ms per 67.5 s loop). **Tunes 4–8 are one-shot**: they open `00 8n 00 92 ii`, place `9C` near the end with no NOTE ON inside the loop, so they play once (2.7–8 s) and then loop a silent tail forever while remaining the "current" tune — the game's `AH=9` poll therefore never restarts them (`[PROVEN]` by the byte walk; the model plays the data as is).
- **Pitch** `ComputeFnumBlock +0x503`: `e = (note + inst[8] − 0x18) & 0xFF` (percussion: `e = inst[8]`); `x = e·64 + (bend − 0x40)·bendRange` (signed 16-bit); F-number = `FnumTable768[+0x0A38][x mod 768]`, block byte from `+0x09D3[(x·4)>>8]`; table entries with bit 15 → block+1 with halved fnum; `semitone < 7` → fnum >>= 1. Driver note `n` = MIDI `n+12` (60 → C5, 523.4 Hz, fnum 690 block 4).
- **Volume** `SetVolumeRegs +0x567`: idx ≈ `(L+1)(V+1)(C+1)/16384` (L = carrier level inst[B], V = velocity, C = slot volume 7F, master `+0x1256` = 00FF never written) → `VolumeToAttenTable[+0x10CC][idx]`; carrier gets `KSL | atten`, modulator gets `inst[A]` raw (or scaled too when `inst[9] & 1` = additive). **There is no volume/fade API.**
- **Instrument record** (16 B): `[0] 60h op1, [1] 60h op2, [2] 80h op1, [3] 80h op2, [4] 20h op1, [5] 20h op2, [6] E0h op1, [7] E0h op2, [8] transpose, [9] C0h feedback/connection, [A] modulator level, [B] carrier level, [C] KSL bits (5:4 → op1, 1:0 → op2), [D][E] unused, [F] bend range`. Write order at load: 60,60,80,80,E0,E0,C0,20,20.
- **Sfx allocation** (`CmdPlaySfx +0x6C8`, `ProcessSfxStartQueue +0x704`, `StartSfxOnSlot +0x722`, `FindFreeSlot +0x784`, `FindFreeOplChannel +0x7BE`): engine ids are not queued twice; the queue is 8 entries, a full queue replaces a lower id; the tick drains entries in order, clearing each before starting it (a failed start drops that id, the rest wait); a sfx takes the first free slot and the **highest free OPL channel from 8 down** (`+0x7C1–7D7`: try 8, restart the slot scan for 7, …); **with all 9 channels busy** (`+0x7D9`) the request is dropped (`INT3`/`STC`) *unless* some state-2 slot has an id ≤ 7, in which case the routine returns success with **channel `0xFF`** (`JNG +0x7FF` never frees or steals anything): the new sfx occupies a slot whose register writes go to `A0h/B0h + 0xFF` and to operator offsets read from beyond the 9-word table — garbage registers, nothing audible from that slot, and it holds its id so `AH=10` reports it playing. **`UNKNOWN_channel_exhaustion` resolved (M3.28, 2026-09-23, re-disassembled live `07BE-0803`): the shipped game is one voice away from this path (8 of 9 busy observed live, four engines plus overlapping drop-in sfx 9) but has never been seen taking it; the port previously dropped in BOTH cases (genuine exhaustion and the phantom-success case) — now ported exactly: `Sequencer.startSfx` checks for a state-2 slot with `sfxId <= 7` before dropping, and takes the phantom `channel: 0xff` path if one exists.** Every downstream register-write path (`noteOn`'s `0xA0|ch`/`0xB0|ch`, `instrumentOplRegs`'s `0xC0+ch`) was re-verified against a fresh disassembly of `NoteOnSetFreqKeyOn`/`LoadInstrumentOperators` to confirm `OR` vs `ADD` exactly (both fold `ch=0xFF` onto a garbage register the OPL2 core already no-ops on) — no changes needed there, only in `startSfx` itself. The all-16-slots-busy "steal" pass is buggy (`MOV CH,[DI+0xA]` clobbers the loop counter and `LOOP` re-enters pass 1): slot 0 in state 2 → a same-id scan that overruns the slot table; state 1 → the next music slot handed out as free — unreachable with the shipped call patterns. `[STATIC]`
- **Engine sounds**: the four 16-byte records at `+0x08..+0x47` are the sequences of sfx `0x40–0x43`: `00 | 92 ii | 00 | 9C | 00 | 23 7F | 01 | 95 bb | dd | 98` — instrument, loop point, note 35 vel 127, pitch bend, delay, jump. `MICROU.EXE` writes `ii` (0x70/0x71 by vehicle class), `bb` (speed/10, +0x30 airborne), `dd`, and `98`↔`91` (`1000:7A97`, `1000:7B46`), then keeps `sfx 0x40+car` looping with the `AH=10`/`AH=5` pair. Live: the 272 bytes that differ between file and resident driver are exactly these bytes, the shadow, the variables and the slots.

## 4. `DRIVER2.BIN` (PC speaker) and `DRIVER0.BIN` (none) — ported, the driver state `[PROVEN]` live

Same entry shape (`+0x00`/`+0x04` → dispatcher `+0xF7`, max command `[0x124]` = 0 until `AH=0`, then
0x10; table `+0x125`, 17 handlers), same container and sequence grammar (bank pointers `0x749/0x74B/0x74D`
→ music `0x074F` (8 tunes, per-driver arrangements of 2–3 tracks), sfx `0x2CBE` (**15**), instruments
`0x2DE5` (only `+8` transpose and `+9` gate are read)). Re-disassembled in full (`ndisasm -b16`,
`0x0F7–0x688`) and ported as `src/formats/beeper.js`, a transcription over the image as memory:

- **Memory**: `0x73` host divisor, `0x75` track count, `0x77` pending tune, `0x78` current tune, `0x79`
  pending stop-music, `0x7A` pending reset, `0x7B/0x7C` division/tempo, `0x7D` tick guard, `0x7E`/`0x82`
  music increment/accumulator (16.16; the integer at `0x84`), `0x86`/`0x8A` sfx (`0x8C`), `0x8E` last
  PIT count, `0x90` round-robin counter + `0x91` slot table, `0x99` engine alternation, `0x9A` engine
  voice mask, `0x9B/0x9D` the two engine periods, **4 slots** × 0x12 at `0x9F` (`+0` stream, `+2` 32-bit
  counter, `+6` loop, `+8` channel, `+9` note, `+A` state 0/1/2, `+B` sounding, `+C` instrument ptr,
  `+E` sfx id, `+F` period, `+11` gate countdown), start queue `0xE7`, stop queue `0xEF` (8 each).
- **Tick** `0185`: reset → stop-music (both clear **all four** slots, sfx included) → start the pending
  tune (at most 4 tracks; all slots cleared first) → the **start** queue → the **stop** queue (the reverse
  of DRIVER1's order) → accumulate → advance the slots → clear the integers → output.
- **Slot** `01E0`: the gate counts down every tick and silences the slot at 0; events fire on the
  counter's borrow, as DRIVER1. A note: period from the 96-word table at `0x689` indexed by
  `note + transpose − 0x18` (out of range keeps the old tone), and it sounds for the instrument's gate in
  ticks. `90` note-off-if, `91` end, `92` instrument, `93` tempo, `94–97`/`9B` skip 1, `9D` skip 2,
  `98`/`9C` loop, `99` note off, `9A` sleep; any opcode above `9D` ends the track.
- **Output** `0307`, one tone per tick on PIT channel 2 (mode 3, `43h ← B6h` at init): while the engine
  mask is non-zero **and no slot holds an sfx**, the two engine voices alternate tick by tick; otherwise
  the next sounding slot in round-robin order (chords arpeggiate at 70 Hz); nothing sounding → the gate
  bit off. The count is written only when it changes (hi byte masked to 5 bits).
- **Commands**: 0 init, 1 shutdown, 2 divisor (the same rem:quot `DIV` quirk as DRIVER1), 3 tick, 4 tune,
  5/8 queue (first free byte, no dedupe, no priority), 6/7 pending reset/stop, 9 `AL − current`, `0A`
  0 if some slot holds the id, `0B` count, `0C`/`0D` constants, `0E/0F/10` the engine voices.
- **sfx 16–18: dropped.** `0459 CMP AL,[bank]; JA` skips any id past the bank's count before a slot is
  taken. So the race-over jingle (`30DF`, id 16) is silent under SPEAKER, and `AH=0Ah` reports it "not
  playing", so the Winner/1 Up! keep-alives re-queue it every call, harmlessly. `[PROVEN]` live below.
- **`DRIVER0.BIN`**: `MOV AX,0; RETF` at both entries. Every command answers 0, so `AH=9` says every tune
  is current and `AH=0Ah` every sfx playing: nothing is ever re-queued, nothing sounds.

**Live** (`[PROVEN]`, 2026-09-26): SOUND set to SPEAKER on GAME OPTIONS (the dirty flag `[0F63]` poked to
0 first so RETURN would not rewrite `game/SETTINGS.DAT`), then a Python sampler read the driver's bytes
`0x60–0xFF` (live segment `1662`) with the game tick `DS:28F7` on either side, one snapshot per tick:
- `tools/refs/si2/drv2_title.json`: tune 1 on the title. Seeded from one snapshot, the model reproduces
  every later one byte for byte (1545/1545 in the full capture, 799 in the committed excerpt).
- `tools/refs/si2/drv2_poke.json`: sfx 1–18 written into the start queue every 1.3 s while running,
  then the engine bytes `0x9A–0x9E`, an sfx during engine mode, and off. 2222 snapshots match; the only
  differences are the pokes themselves. Here most starts were consumed between two snapshots, so this
  capture proves the playback after each start and the 384 ticks of engine alternation, not the start.
- `tools/refs/si2/drv2_sfx.json`: the start routine itself -- ids 1–18 queued with the emulator paused
  (`debug/pause`, the tick guard `[7D]` checked 0), a snapshot taken with the id in the queue, then
  resumed. 1884 snapshots match with no unexplained difference; the model's own start routine started
  ids 1–15 from the queue, and **16–18 never reach a slot**.

**Port**: `src/audio/speaker.js` renders the output as a band-limited square wave at `1193182/count`
(level 0.2, a port choice); `si2-worklet.js` hosts `BeeperDriver`/`NullDriver` by `kind`; `npm run tunes`
also writes `tools/out/SPEAKER_*.wav`. The game side is `docs/engine.md` §9cq. Not established: how the
real speaker sounds (the waveform through a PC speaker cone is a render, not a capture).

## 5. The JS port

- `src/formats/si2.js` — `Driver` (banks, tables, the arithmetic replicas) and `Sequencer` (16 slots, the byte-code, `command(ah, al)` with the pending pipeline and the two 8-byte id queues, `hostTick()`, a mutable driver image with `patchEngineRecord()`, and `engineUpdate(car, {bend, instrument, delay})` = the game's per-step engine idiom).

- The viewer's `DRIVER1.BIN` page plays tunes/sfx/engine and shows the live channels.

## 6. What a port must do to sound like the game

Keep the driver model (`Sequencer`) as the only source of register writes and drive it exactly as `MICROU.EXE` drives the real one:

- **Reloads, not resets.** The game creates a fresh driver (new image: shadow `FF`, slots 0, file accumulators, `[1258] = 0`) at every `LoadSoundDriverBinModule` call — `1000:0051` and `0066` on RETURN from GAME OPTIONS, `26E4` after ESC from a race, `29B0` on F3 (which reloads the *old* driver number) — and then issues its fixed sequences: title entry `AH=4(1), 7, 8, 6, 9, 4(1)`; `AH=9`-then-`AH=4` pairs everywhere (the attract loop every 4 s); `AH=7` at race start (`11AA`) and again at `39F5` ~20 ticks after the engines were queued; pause `AH=8` (leftover AL), `AH=6`; race end `AH=5 10h` (gated on a car being drawn, BX = `UNKNOWN_bx_at_30df`), `StopEngineSounds`, 100 banner frames, `AH=8` (leftover AL), `AH=6`, then tune 8/6 on the results screen (`1439`/`1C84`). The sticky-StopMusic double start, the `39F5` engine kill and the tune-start freeing of all 16 slots then fall out of the model. Do **not** hard-code idle ticks between load and first tune (§1): model the `CS:3279` gate (no driver ticks while the load is in progress) and let the frame/tick interleaving decide.
- **Timing.** One `hostTick()` per 70 Hz frame, two per 35 Hz physics step; never run the sequencer at 192 Hz — the 2/3-sequence-tick quantisation is part of the sound. Seed division/tempo and the eight timing words from the image, recompute increments on `AH=2`, tune start and opcode `93`, carry the 16.16 fractions across commands (only a reload resets them). Stamp commands with the game tick so the worklet applies every command with stamp ≤ T before running tick T (2–3 ticks of lead absorb message latency), or run the sequencer on the main thread in lockstep with physics and ship `(tick, reg, val)` with sample timestamps — otherwise replay tests against captures are impossible.
- **Engines** (`Sequencer.engineUpdate`, from `1000:7B46`): per car `c` (0..3, or 0..1 with two players; the whole update is skipped while any car's state word is `0Bh`): `bend = min(|speed [BX+127A]|, 7FFh) / 10`; `+30h` airborne (`[BX+12D4]`); `= 14h` when `[BX+1382]`; `= 0Ah` when the car was not drawn (`[BX+1250] == 0` — **the engine site is not gated on "drawn"**, off-screen drones idle audibly); then `bend = |bend + ((rand & 3) − 2)|` with `rand = AdvancePseudoRandom48 1000:7CAE`. Record `+0xA = bend`, `+0xC = 98h`, or `91h` when the bend is 0 (no command — the loop ends by itself); for a non-zero bend `AH=10` then `AH=5` only if it answers "not playing" (`7C0E–7C1F`). Instrument byte `70h` for classes 2 (POWERBOATS, live-corroborated) and 8 (CHOPPERS, assumed) else `71h`, delay byte 3 for class 8 else 0, written once at race start (`1000:7A97`). Bends ≥ `40h` are a positive offset (unsigned borrow in `+0x551`, up to +8.9 semitones at range 3) — routine for drawn cars at speed ≥ 640 but never captured live. **`UNKNOWN_engine_high_bend` resolved (M3.28, 2026-09-23): `ComputeBendOffset 0x0551` re-disassembled live byte for byte (`SUB AL,0x40` then `JC` on the 8-bit unsigned borrow selects the negative-offset path; the no-borrow fall-through is `(bend-0x40)*range`) confirms the port's own `Driver.bendOffset` was ALREADY exactly correct for the whole 0..0xFF bend range, not just the ≤0x0B the live captures ever exercised — no code change, only a synthetic test (`tools/check-si2.mjs`) exercising bend values up to the documented `0x7F`/range-3 "+8.9 semitones" ceiling, each checked against the hand-computed formula. Still `[STATIC]` in the sense that no live capture has bend ≥ 0x40 (that would need a drawn car at speed ≥ 640, harder to stage live than to verify by disassembly), but the formula itself is no longer an open question.**
- **The jitter PRNG** `AdvancePseudoRandom48 1000:7CAE` `[STATIC]`, three overlapping words at `CS:7CDB..7CDE` (file `45 23 56 26`): `w0 = (w0 ^ 234h) + 2244h` (carry C1); `w1 = ((w1 + w0 + C1) & FFFFh) ^ 22ABh`; `w2 = ((w2 + 233h) & FFFFh) ^ 5345h`; return `w2` (the XORs clear CF, so the last ADC is a plain ADD). Only callers: `7BD9` (engine jitter) and `7C90`. Corroboration: this recurrence reaches the race dump's state `45 90 69 B2` after exactly 6204 calls; a carry-preserving variant never does. Own it in the sound layer — it is deterministic given the per-car call order. **Ported M3.7 (2026-09-21), `createEngineJitter()` in `src/formats/si2.js`**: the byte-level order matters and was read live at `1000:7cae-7cda` to get it right — each word is written back to memory *immediately* after being computed, so the next word's read already sees the previous word's just-written high byte (a genuine one-byte memory overlap, not three independent registers read together then written together); a first attempt using the latter (obvious but wrong) reading did not reproduce the `45 90 69 B2` checkpoint, the corrected byte-sequential version does exactly (verified in `tools/check-sound.mjs`).
- **Events.** All 36 `AH=5` sites are disassembled and predicated in §3b (per-id table, cross-references, Ghidra `[STATIC snd]` EOL comments at every address); implement each as its physics is ported, gate on the renderer's "car drawn this frame" (`[BX+1250]!=0`) — **except** the engine loop (`7C1F`) and the three id-16/15 banner-loop sites (`85FD`, `8695`, `86BA`), which have no draw-flag test at all and instead loop on the `AH=0Ah` "already playing?" idiom — and keep sfx 4/5/7 OPL-only. The per-id table still rests on rendered-but-unheard audio (`UNKNOWN_sfx_semantics` downgraded, not closed — see §3b's acoustic notes) and on class 8 = CHOPPERS being unverified beyond internal consistency. - **OPL.** Never write reg 01/08/BD; 9 melodic channels, music on 0–7, sfx from 8 down; drop on channel exhaustion (§3). The register stream is proven, the synth is not (`UNKNOWN_opl_sample_fidelity`): validate `src/audio/opl2.js` against a reference core on the same register stream, or adopt one.
