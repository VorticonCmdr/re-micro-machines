# Race graphics: tile banks (`.PR0/1/2`), the world map, vehicles (`.VH0`), `BITSFILE.PH0`, and the video pipeline

Evidence tags as in `CLAUDE.md`; addresses are Ghidra program `MICROU.EXE` (`1000:`-based, `DS = 193C`; segment immediates written Ghidra-relocated, i.e. file value + 0x1000). Established by the research workflow's `video-and-blit` agent (complete OUT/IN enumeration and blit-loop disassembly), ported to `src/formats/race.js`, and **verified pixel-exactly against a live DOSBox frame** (`npm run live`).

## Video pipeline `[STATIC]`, geometry `[PROVEN]` by the live diff

- **Mode 13h only.** `real_entry` does `INT 10h AH=0Fh` then `AX=0013h` and never touches the mode again. All 42 `OUT` and 36 `IN` sites are classified: keyboard 60h/61h + PIC 20h, joystick 201h, PIT 40h/43h, Sound Blaster DSP `base+6/+A/+E` (1000:3a7b–3acc), DAC 3C8/3C9 (only 1000:3303/331f), CRTC 3D4/3D5 index 11h only (retrace IRQ), attribute controller 3C0 index 11h (overscan, 1000:8b8e), status reads 3C2/3DA. **No sequencer, no graphics controller, no CRTC start address: no Mode-X, no page flipping.** (`FONT.BIN`'s own planar writes are the code-card screen, not the game.) `UNKNOWN_modex` is closed.
- **Back buffer**: one 272×240 8-bpp buffer (`0xFF00` bytes) at segment `7D78` (just below the stack). Menus compose at (8,8), races at (16,16). Both copy a **256×200 window to `A000:0020`** — screen x 32..287, 32-px black bars either side (`CopyWholeFrontViewToVga 1000:08bc`: 200 rows × 64 `MOVSD`; `CopyRaceViewToVga 1000:92bc`: 200 rows × 128 `MOVSW` from `0x1110 − fineScroll`). Confirmed by the live frame: columns 0–31 hold the HUD, 288–319 are black.
- **Palette**: `LoadPalFileToDac 1000:07a0` reads 0x300 bytes and uploads via `INT 10h AX=1012h`; race palettes go through `PaletteFadeUpFromBlack 1000:32ce` (64 steps of +1 per DAC byte) / `PaletteFadeToBlack 1000:327a` (63 steps of −1), uploading 768 bytes straight from memory with no shifts (`1000:331f–3330`). No palette cycling exists. Round 3 patches DAC entries 251–253 from 219–221 (race 2) or 235–237 (race 1) (`1000:4795–47f4`). The live DAC during a round-2 race equalled `ROUND2.PAL` in all 768 bytes, and `round(v·255/63)` reproduces the DOSBox frame exactly.
- **Frame pacing** (`1000:4a21–4add, 490d–4965, 3061–30dd`): a vsync counter at `CS:4ADE` is bumped by the VGA vertical-retrace IRQ (INT 0Ah, CRTC 11h) or, if that never fires, by an INT 8 timer re-locked to retrace by polling 3DA. `RunRaceMainLoop` runs `smoothness` (1..4) physics steps per drawn frame and waits for counter > {1,3,5,7}[N]: **physics 35 Hz, display 35/N fps**; AUTO (5) measures loops per retrace at startup.

4. Overlay tiles (map bit 15) re-blitted **transparently from tile (index+12)** after the cars (`1000:9214–9237`: `MOV SI,0C00h` = 12 × 256).

The full per-iteration order of `RunRaceMainLoop` (of which this composition is one step) is in `docs/engine.md` §2.

## The world map (memory only) `[PROVEN]` by the live diff

**192×192 little-endian words at `4B78:0000`** (row stride 384 B, `0x12000` bytes), toroidal: the world is 3072×3072 px and wraps (`1000:917a–91e9`: `CMP DL,C0h`, `CMP BL,C0h`). Entry bits 0–14 = tile index into the PR bank (`tile byte offset = idx·256`), bit 15 = overlay.

It is built before each race by `InitRaceCarsFromTables 1000:448c–4575` (a verified interior span of the function `InitRaceCarsFromTables 1000:3c09–458a`, `docs/engine.md` §2): for every `.MAP` cell (32×32 cells of 6×6 tiles = 96×96 px) the `.CT` record of the cell's tile index — **72 bytes = 6 rows × 12 bytes = 6×6 words** — is copied in place (row stride 0x180). So **`.CT` is the meta-tile table: 6×6 tile indices per 96-px map cell**, and `.CT = 4 × .COL` because 72 = 4 × 18. **Correction (`docs/engine.md` §2/§9): the bit-15 pass belongs to a different function, and its ranges are closed, not open.** `1000:3994–39e4` runs inside `LoadRaceStartPosCheatsMapAndBanks 1000:38fb`, not inside `InitRaceCarsFromTables` (they are sibling calls from the race-setup sequence, `docs/engine.md` §2 Table 2). The pass is gated on `byte [DS:042E] == '1'` (the last character of the game-set name "GAME1", always true for the shipped set) and is **hard-coded, not table-driven**: round 2 → words `0x40..0x13C`, round 3 → `0x01..0x51`, **every other round → no overlay at all**. `UNKNOWN_overlay_ranges_other_rounds` is closed: there is no round→range table to find. `buildWordMap()` implements this; `renderTrack()` draws it.

**Verification (`tools/check-live.mjs`).** The live boot trace captured the `A000` frame buffer during POWERBOATS round 2 race 1. An exhaustive 1-px camera search over the rendered 3072×3072 world found camera (414, 500) matching 98.8% of a static region; at that camera **every pixel of the 256×200 view matches the render except the HUD column and the boat sprite** (1267 differing pixels, 0 outside those two boxes). The `.MAP → .CT → .PR` chain is therefore `[PROVEN]` for round 2 race 1 (one frame, one round); for the other rounds it is `[STATIC]` plus the consistency check that every map's max referenced tile is < its bank size (e.g. 508 of 509, 442 of 443) and that all 29 renders look like coherent courses.

**Overlay tiles (bit 15) — what they are.** For every flagged tile in the live view, tile `idx+12` holds the *same graphic with the background cut to colour 0* (128–192 opaque pixels of rack bar, transparent water; 0 pixels differ from the base tile). Redrawing it therefore changes nothing in a static render — the pass exists so foreground bars are drawn again **over the cars**, i.e. vehicles pass *under* the bath-mat rack. Because the live frame has no car under a rack, the overlay path itself stays `[STATIC]` (`1000:9214–9237` is unambiguous about the mechanism; only its visual effect is unobserved). One flagged index in round 2 (191) has an overlay that differs from its base — `UNKNOWN_overlay_tile_191`, closed: a car under it is drawn exactly as live (`docs/engine.md` §9dr 9).

Quirk: `ROUND82.MAP` references meta-tile 58 and `ROUND92.MAP` 60, beyond their `.COL`/`.CT` counts (49, 59) — the game reads past the loaded table into whatever follows in DS. **`UNKNOWN_tile_index_overflow` resolved (`docs/engine.md` §9ac/§9ad):** both cells are structurally unreachable by any car (a full sub-cell flood fill from each race's own start position never touches even their tile boundary). The `.CT`/render-bank visibility question (whether the same cells could still be *seen* near the track edge even though never *driven on*) is now also closed, not just deferred: the same flood fill's own distance data shows the nearest reachable point is 264-744 world units from these cells, well beyond the camera's own ~128/~100 half-width/height (`docs/engine.md` §3), so they can never enter the camera's own viewport either — confirmed unreachable both ways. `npm run render`/`npm run tracks` run clean for both rounds without crashing, consistent with this.

## Tile banks `ROUNDnBR.PR0/1/2` `[PROVEN]`

`LoadRoundPrSeries 1000:45ef` → `LoadCompressedSeries` with `ROUNDnBR.PR0` to segment `2B78`: PR0, PR1, PR2 LZ-unpacked into 48 KB slabs = **one contiguous bank of 16×16 opaque 8-bpp tiles, 256 B each** (blit `1000:918e`: 16 rows × 8 `MOVSW`). Sizes: rounds with PR2 up to 576 tiles; rounds 5/7/8 fit in two slabs (that is why they have no PR2). Tile counts: 509, 443, 472, 502, 312, 485, 346, 285, 495. `CopyPr0HeaderToDs 1000:4808` copies tile 0 (256 B) to `DS:3EE3` (read by `FUN_1000_8996` — `UNKNOWN_pr0_header_use`). Palette `ROUNDn.PAL`. Rendered banks show the desk (pencils, notepads, sums), bathtub (water, bubbles, soap, rack), etc.

## Vehicles `ROUNDnBR.VH0` `[PROVEN]` by render

`LoadRoundVh0AndSplit 1000:4611`: LZ-unpack; copy `0x1440` bytes to `5D78:0000` (bank 1) and the next `0x1B00` to `6D78:0000` (bank 2); round 9 uses `0x3840` / `0x1F40`. Bank 1 holds **9 frames of 24×24 (576 B), headings 0°..90° (0 = up, 8 = right)**; `ExpandVehicleRotations24 1000:4696` builds frames 9..31 by mirroring: `f[9+k] = vflip(f[7−k])` (k 0..7), `f[17+k] = hflip(f[15−k])` (k 0..6), `f[24+k] = hflip(f[8−k])` (k 0..7). Heading `a` (0..255, clockwise) → frame `a >> 3`. **Round 9 (Ruff Trux) stores 40×40 frames (1600 B), 9 in bank 1 and 5 in bank 2, no mirroring** (`1000:46f6`). **`UNKNOWN_vh0_bank2` is closed in general (`docs/engine.md` §1/§4/§9): bank 2 holds the animation frames for car states 1, 4 and 5** — the hazard-death sequence (state 1, via the per-class step tables `27C1`/`27DD`/`27F9`/`2835`), the fall animation (state 4, table `2879`) and the crash animation (state 5, table `2855`), all drawn by `DrawSprite24FromSecondBank` (`HandleCarState4FallAnimSfx8`/`HandleCarState5CrashAnimSfx8`; round 9 via `DrawSprite40FromSecondBank`). Separately, **for round 8 (CHOPPERS) specifically the same buffer is dual-purpose**: `1000:4676–468F` copies the bank's first `0x1400` B to `DS:5EE3`, but only when `[0x28BF]`(round)`==8` — reinterpreted there not as 24×24 frames but as **5 frames of 32×32**, and rendering them with `ROUND8.PAL` shows a spinning helicopter rotor blade (`[PROVEN]` by render, `tools/render-bitsfile.mjs` / `ph0ChopperRotorFrames`). `DS:5EE3` is the exact offset of `BITSFILE.PH0`'s resident buffer at `+0x1F00`, which is otherwise (round 2) a live PH0 sprite in its own right — see below.

Drawing (`1000:8c3c–8dfb`): colour 0 transparent; **body colour remap** `BlitSpriteCarColourRemapRace 1000:8c6a`: for `p ≠ 0` with `(p & 0xF) ≤ 2`, `p += carColourOffset` (`[car+0x1252]`); **shadow** `BlitSpriteSilhouetteBlack 1000:8c3c`: every non-zero pixel → colour 0, drawn at (x+z, y+z) while the body is at (x−z, y−z), airborne only. `ClipSpriteToRaceView 1000:8bab` clips to 256×224; the `AtXY` variants only reject wholly off-screen sprites and rely on the buffer's 16-px margins.

## `BITSFILE.PH0` `[PROVEN]` by render, layout `[STATIC]` (mostly closed)

LZ-unpacks to 26048 B (`0x65C0`), copied to `DS:3FE3` every race (`LoadBitsFilePh0 1000:482f`). Offsets below are from the unpacked start; the decoder is `src/formats/race.js`'s `PH0_LAYOUT` + `ph0*` functions, rendered by `tools/render-bitsfile.mjs` and `src/ui/views/raceGfxView.js`'s `bitsfileView`.

- `+0x0600–0x1380` (3456 B) — **`UNKNOWN_ph0_0600_1380` is closed (`docs/engine.md` §4, §9cf).** `+0x0600–0x1140` (2880 B = 5 frames × 576 B) is the state-2/0xD "re-appear" and knockout animation: `DS:45E3` (`= PH0 + 0x600`) is the frame base read by the shared handler for states 2 and 0xD (`1000:82be`, `docs/engine.md` §4), which indexes it as **5 distinct 24×24 frames** (ids 0,1,2,3,4, then 0 again — 6 table entries, 5 frames, from the duration/frame-id tables at `DS:289D`/`DS:28AB`) via `8339` (`SI = frame·576 + 0x45E3`), drawn at the car's frozen knockout position `[BX+0x12BA]/[0x12BC]` minus height minus camera. **`+0x1140–0x1380` (576 B) is a 6th 576-byte slot the frame table at `DS:28AB` never selects** — `UNKNOWN_ph0_1140_1380`, closed in `docs/engine.md` §9cf as an unused asset (three small icon shapes).
