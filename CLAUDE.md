# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

> **Evidence discipline.** This directory is a reverse-engineering target, not a source repo. Tag every recorded claim with how it was established, and label anything not established `UNKNOWN_<identifier>` instead of guessing:
> `[PROVEN]` = verified by executing something (ran the code, traced it live under DOSBox, decoded bytes and looked at the result).
> `[STATIC]` = read out of the bytes (strings, headers, `ndisasm`/Ghidra disassembly, size arithmetic) but not confirmed at runtime.
> `[UNKNOWN]` = not established.
> Everything in this file is `[STATIC]` unless marked `[PROVEN]`.

## What this is

The installed DOS release of **Micro Machines** (Codemasters, 1994; `INSTALL.DAT` is dated 9/9/94), living in `game/`. The game itself has no source code; the only code in this repository is the port/viewer under `src/` and `tools/` (see Commands). Treat everything under `game/` as software archaeology. The pristine archive is `../micro_machines.zip` (164 files plus 2 directory entries — `unzip -l` reports 166). `game/` holds those 164 plus two user-added files, `MICROU.EXE` and `UNP.EXE` (see below). The 164 are exactly `INSTALL.DAT`'s 162 `COPYFILE` lines plus the two `CHKLIST.MS` files. `game/SETTINGS.DAT` carries a 2008 timestamp in the archive — it was re-saved by someone playing, so it is runtime state, not distribution content.

Credits string in `MICROU.EXE`: code Lyndon Homewood, Gary Ranson, Jon Cartwright; music Gez Gourley; graphics Brian Hartley, Mark Neesam, Pete Ranson; produced by Big Red Software.

## Executables and the launch chain

| File | What it is |
|---|---|
| `MICRO.COM` (472 B) | The launcher (`INSTALL.DAT`: "type MICRO"). Shrinks its own memory block (`INT 21h AH=4Ah`), then `EXEC`s (`AH=4Bh AL=0`) **`SM.EXE`**, then **`MICRO.EXE`**, saving/restoring `SS:SP` around each call; afterwards sets text mode 3 and exits. Both children are mandatory (`Cannot find file SM.EXE` / `MICRO.EXE` paths). Disassembled with `ndisasm -b16 -o 0x100`. |
| `SM.EXE` (4832 B, MZ, 0 relocs) | The Codemasters **"Absolutely Brilliant!" logo intro** in mode 13h (`[PROVEN]` by rendering `GFX1.GFX` with its own draw tables — see `docs/intro-and-codecard.md`). Not the copy protection. Its exit code is garbage and nothing reads it: there is no handshake with `MICRO.EXE`. Holds the `GFX1.GFX` palette (file 0x56C) and draw list (file 0x21E). |
| `MICRO.EXE` (28955 B) | The game, **PKLITE-packed** (banner `PKLITE Copr. 1990-92 PKWARE Inc.` at offset 0x1C; 1 relocation, entry `FFF0:0100`). `file(1)` misreports it as a PKZIP self-extractor — ignore that. Do not disassemble this one. |
| `MICROU.EXE` (83662 B) | **The unpacked form of `MICRO.EXE`, user-produced, and the Ghidra import target.** Not part of the original release. Well-formed MZ: header-declared size equals file size, 72 header paragraphs, 279 relocations, entry `CS:IP = 1423:000D`, `SS:SP = 7D78:0400`; every game string is plain text in it (see "Anchors" below). That it is a *faithful* unpack of this exact `MICRO.EXE` is consistent with the headers (`minalloc` 0x69A2 vs the packed 0x76BB) but not proven — no reference hash exists. Whether it runs standalone without `MICRO.COM` is `UNKNOWN_microu_runs_standalone`. |
| `UNP.EXE` (20106 B) | User-added; by name and by this user's established workflow it is Ben Castricum's UNP executable expander (the sibling `Pushover` project used UNP 4.11 on its PKLITE/ProPack binaries, and `../unp4-src/` is UNP 4.12's source). Its own banner is not visible in `strings` because the binary is itself compressed, so the exact version is `UNKNOWN_unp_version`. Only needed if `MICROU.EXE` ever has to be regenerated. |
| `INSTALL.EXE` + `INSTALL.DAT` | LZEXE-packed DOS installer and its plain-text script. `INSTALL.DAT` is the authoritative manifest of the DOS install (`MAKEDIR GAME1`, one `COPYFILE` per file) and confirms `game/` is one complete install. |

## Loadable code modules (`.BIN`)

Not every `.BIN` is data. These are real 8086 code modules loaded into the slot `2424:0000` and far-called:

- `DRIVER1.BIN` (28625 B) — the **Sound Images Generation 2 OPL2/AdLib driver** (Tony Williams), selected by `SOUND = BLASTER`. **All music (8 tunes), 18 sfx and 128 instruments are embedded in it**; the game only passes tune/sfx numbers and pokes the four engine-sound records at `+0x08`. Command = AH at one far entry (`+0x94` dispatcher, table `+0xC4`), ticked at 70.06 Hz by the game's IRQ0 ISR (`AH=3`). Fully decoded and ported (`src/formats/si2.js`, `src/audio/`); `docs/sound.md`.
- `DRIVER2.BIN` (11845 B) — "Internal Beeper v1.08", the PC-speaker driver (`SOUND = SPEAKER`): same command set and container, speaker arrangements of the same tunes; not ported.
- `DRIVER0.BIN` — 8 bytes: `mov ax,0; retf` twice, the null driver (`SOUND = NONE`).
- `FONT.BIN` (27084 B) — **not a font: the code-card copy-protection module.** `MICROU.EXE` loads it into the same slot at startup (`LoadAndRunFontBinCodeCard 1000:31f0`), far-calls it with AX=0, and exits to DOS unless it returns 0 (`real_entry 1000:0009`). It runs in mode 10h, draws an 8×8 grid of 64 symbols (planar bitmap at +0x26CA) and holds the physical code card as a 16×16 table at +0x68CC. **Both compare sites are byte-patched in this copy** (+0xAB, +0x13A → `MOV AL,DL` + jump/NOPs), which is why any answer passes. Decoded in `src/formats/fontbin.js`; details in `docs/intro-and-codecard.md`.
- `ANTIFONT.BIN` — **0 bytes, in the original archive as well.** `SM.EXE` expects a 91-glyph 11×13 proportional 8-bpp font here (13013 B) for its copyright line; with the empty file nothing visible is drawn and nothing breaks.

## Data files

Every format below is documented with its consumer's disassembly address in `docs/`; the summary here is what a session needs to orient.

**One LZ codec for everything packed** (`DecompressWorkBuffer 1000:3333`, ported in `src/formats/lz.js`, byte-identical to an independent transcription on all 41 files): `COMPRESS.PI0–6`, `ROUNDnBR.PR0/1/2`, `ROUNDnBR.VH0`, `BITSFILE.PH0`. `LoadCompressedSeries 1000:3547` patches the last filename character `'0'+n`, unpacks each file and lays them out at 48 KB strides until an open fails. The game never allocates memory: every buffer is a fixed segment (`docs/asset-arena-and-lz.md`).

Top level:
- `COMPRESS.PI0–6` — one 328 KB **front-end asset arena** (segment `2B78`) cut into 48 KB slabs. Its 18 `.CHR` members (faces, vehicle miniatures, logo, fonts `0-9 A-Z ! ?`, the vehicle display case as an 8×8 tile map) are described by `chrDescriptorTable` at `DS:0A14` (20-byte records; the two dimension words are **height, width**). Palette `INTRO.PAL`.
- `BITSFILE.PH0` — shared race graphics (26048 B unpacked → `DS:3FE3`): wheel/wake puffs, "1st".."4th" labels, HUD icons. Opened as `..\BITSFILE.PH0` because the game `chdir`s into `GAME1` for each race.
- `GFX1.GFX` — the logo intro's sprite pack (`SM.EXE`; `src/formats/gfx1.js`). `INTRO.PAL` — menu palette. `SETTINGS.DAT` — 8 words (P1/P2 control, smoothness, **sound driver 0–2**, joystick thresholds) + 16 scancodes, read on first options entry, written only when changed. There is no Sound Blaster PCM path anywhere: `BLASTER` means OPL2 via `DRIVER1.BIN`.
- `.PAL` files are 256 × RGB **6-bit DAC values used verbatim** (`[PROVEN]` live: DAC == `ROUND2.PAL`); convert with `round(v·255/63)`.

`GAME1/` is the one shipped "game set" (`GAME?.LVL` files would describe others; none exist, and the code path that needs them is never taken). Per round `n`:
- `ROUNDnBR.PR0/1/2` — the round's **16×16 tile bank** (256 B/tile, opaque, up to 576 tiles; rounds 5/7/8 fit in two slabs, hence no PR2).
- `ROUNDnBR.CT` — **meta-tile table**: 72 B per meta-tile = 6×6 little-endian tile indices. `ROUNDn.COL` — 18 B per meta-tile = 12×12-bit collision mask. `ROUNDn.DIR` — 36 B per meta-tile = 6×6 direction bytes, each packing a terrain grade/ramp nibble and a direction nibble that resolves through two tables to a 16-point-compass heading (the AI flow field). Counts = size/72, /18, /36.
- `ROUNDnBR.VH0` — vehicle frames: 9 stored 24×24 rotations (0–90°) mirrored to 32 at load (round 9: 40×40, 9 frames), plus a second bank.
- `ROUNDn.PAL`, `ROUNDnBR.LEV` (49–64 B, one byte per meta-tile: bit 7 = **not** a projectile line-of-sight block — corrected in `docs/engine.md` §3/§9, it skips only the safe-respawn-point update for that tick — bits 4–2 = one of 8 compass-rose spawn-nudge vectors, bits 6–5 = a respawn heading (also the `.DIR` remap bucket for every car whose current tile it is, `docs/engine.md` §1/§3) — `docs/track-layout.md`), `STRT_POS.BIN` (9×4×{x,y} start positions), `CHEATS.BIN` (30 × 12-byte cheat spots, all 10 effects now decoded in `docs/engine.md` §6).
- Per race `m`: `ROUNDnm.MAP` — 2048 B = a **32×32 grid of meta-tile bytes** (bits 0–5 index, 6–7 attribute) + a second 32×32 plane, now identified as a per-tile **track-progress value** (feeds the wrong-way check and the `.BRK` byte offset below — `docs/track-layout.md`). The world is 3072×3072 px = 192×192 tiles; `MAP × CT × PR` reproduces a live race frame pixel-for-pixel (`npm run live`). `ROUNDnmB.BRK` (29–183 B, none for round 9) — a per-race **AI brake/speed-limit-point stream**, indexed by that same track-progress value (`docs/track-layout.md`).

## Anchors inside `MICROU.EXE` (strings)

The developers left labelled data and menu text in the clear; these are the fastest way into the code in Ghidra:

- Vehicle classes: SPORTSCARS, POWERBOATS, FORMULA ONE, TURBO WHEELS, FOUR BY FOUR, WARRIORS, TANKS, CHOPPERS, RUFFTRUX, PRO FORMULA ONE, PRO SPORTSCARS. Characters: WALTER, MIKE, ANNE, JOEL, CHEN, DWAYNE, JETHRO, CHERRY, EMILIO, BONNIE, SPIDER.
- One contiguous block of track names (`DESKTOP DROPOFF` … `THE LEAFY BENDS`), NUL-walked with index `(round-1)*4 + (race-1)` (empty slots for rounds with 3 races — **except round 2, corrected in `docs/engine.md` §7/§9: round 2's empty slot is its *first*, index 4 = the nameless qualifier `ROUND21`; its other three slots are named `BERMUDA BATHTUB`/`SOAP LAKE CITY`/`FOAMY FJORDS`**); a 26-byte tournament order table at `DS:043C` packs `round<<2 | race-1` (entry 0 = qualifier `ROUND21`, entry 25 = `ROUND14`, which happens to draw "WIN THIS RACE TO BE CHAMPION" for the shipped table — that string is whatever index `(round-1)*4+(race-1)` gives the last entry, not a hard-coded slot). ## Tooling

**Ghidra (`mcp__ghidra__*`).** The project is **`mm`** (`ghidra/mm.gpr` in this directory, opened in the GUI; git-ignored) with **`MICROU.EXE`** imported. Always pass `program: "MICROU.EXE"` explicitly. Ghidra loads the image at **`1000:0000`**; the MZ header's `CS:IP=1423:000D` is only a 7-instruction PKLITE leftover (`MOV [0x5C],0x4B50; AX=DS+0x10; PUSH AX; PUSH 6; RETF`) that far-jumps to the **real entry `1000:0006`** (function `real_entry`). Auto-analysis alone stopped at that stub with 1 function; creating `real_entry` and re-running analysis gave **169 functions** (`[PROVEN]`, this session). Data segment is **`DS = 193C`** (Ghidra-relocated; `SS:SP = 8D78:03E8`). `real_entry` immediately does `INT 10h AH=0Fh` then **`INT 10h AX=0013h` — the game runs in VGA mode 13h, 320×200×256**. Use `disassemble_function` / `disassemble_bytes` as ground truth; the decompiler is for orientation only and every recorded claim cites a disassembly address. Persist names/comments into the project. `SM.EXE` is imported too (33 functions, all named). The MCP tools only see the project while the GUI has it open — check `list_instances` first.

**DOSBox bridge (`mcp__dosbox__*`).** Config: `~/Library/Application Support/dosbox-mcp/config.toml` (engine `dosbox_with_debugger`, heavy debugger, port 8386, `mount_allowed_bases = ["~/Downloads/dosgames"]`). `bridge_start` brings up the managed instance; `drive_mount C /Users/valentin.pletzer/Downloads/dosgames/mm/game`. **Boot recipe `[PROVEN]`:** type `C:` + `MICRO` → `SM.EXE` plays the logo intro (mode 13h, ends by timeout or mouse click) → `MICRO.EXE` runs `FONT.BIN`, the **code-card copy-protection screen** (mode 10h, 8×8 symbol grid, "COLUMN x and ROW y") — **in this copy pressing ENTER on any cell is accepted, twice** because the compares are byte-patched (`docs/intro-and-codecard.md`) → GAME OPTIONS (F1–F6, RETURN to play, ESC quits to DOS). **Menus `[PROVEN]` (docs/engine.md §9ao 7):** `SELECT GAME`/`ONE PLAYER GAME` start with nothing selected and ignore fire until LEFT/RIGHT picks an option; each pick redraws and waits for fire to be released; fire is P1's KEYS2 key S. `input_key` with `pressed: true` is a tap (press+release), so hold keys with `input_sequence` (explicit press/release, ~300 ms holds, ~3 s between a pick and fire). Live CS `0x23E`, DS `0xB7A`. Interrupt breakpoints (`int=0x21, ah=0x3D/0x3F`) only arm after a `debug_pause` → add → `debug_continue` cycle. There is exactly **one** emulator instance — never let two agents drive it at once. `debug_map_to_ghidra` / `debug_map_to_live` correlate live segments with the `1000:`-based Ghidra addresses.

**Quick raw disassembly.** `/opt/homebrew/bin/ndisasm -b16 <file>` for `.COM` and `.BIN` modules (add `-o 0x100` for the COM). `/opt/homebrew/bin/dosbox-x` is available for plain play outside the bridge. Ghidra 12.1.2 itself is at `/opt/homebrew/Cellar/ghidra/12.1.2/libexec/` (`support/analyzeHeadless` works; it was used to produce `re/SM.EXE.lst`).

## Working rules

- Everything in `game/` is the read-only source of truth. `SETTINGS.DAT` is runtime state; `MICROU.EXE` is derived and regenerable from `MICRO.EXE` + `UNP.EXE`.
- Test a format hypothesis against the bytes before writing it down (the `.MAP` refutation above took one script), and record refutations too so they are not re-derived.
- When findings grow beyond this file, split them into `docs/` by subsystem as the sibling projects do (`../Gods/CLAUDE.md` is the mature example), keep the evidence tags, and cite `CS:`/`DS:` offsets from `MICROU.EXE`.
- This is a git repository (`main`, no remote). One commit per finished checklist item (`GOAL-DOS-PARITY.md`); git is the backup, so don't make `.bak`/`.bak2` copies of files being edited.
